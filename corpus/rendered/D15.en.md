
# Runbook: Signature bundle checksum mismatch (SQ-7005)

Applies to SENTRIQ 4.2.

## Symptoms

- Alert `SQ-7005` on one or more relay nodes.
- Agents do not receive the latest signature bundle; detection content is stale.
- **Console → Infrastructure → Relay** shows the bundle in state `REJECTED`.

## Why this matters

A relay that rejects a bundle is failing safe — it will not distribute content it
cannot verify — but the effect is that endpoints run on older signatures until it
is resolved. That is a slow-moving detection gap, not an outage, so it is easy to
deprioritise. Do not: stale signatures miss new threats.

## Diagnosis

**1. Confirm the checksum mismatch**

```
sentriqctl relay bundle-status
```

Read the `checksum` and `expected` columns. A mismatch means the bundle on disk
does not match the signed manifest — the download was corrupted or truncated.

**2. Determine the scope**

```
sentriqctl relay nodes
```

- **One node rejecting** → a local download problem on that node.
- **All nodes rejecting the same bundle** → the bundle at the source is bad, not
  the relays. Do not clear caches; escalate to the content team.

## Resolution

**Single node, corrupted download**

```
sentriqctl relay cache-clear --node sq-relay-01
sentriqctl relay resync --node sq-relay-01
```

The node re-downloads the bundle and re-verifies. Expect a few minutes.

**Slow fan-out after resync**

If signatures propagate slowly after a resync — some endpoints still on the old
bundle after several hours — the relay fan-out is the bottleneck, not the bundle.
Rebalance the relay load and prioritise critical endpoint groups.

## When to escalate

- All relay nodes reject the same bundle (bad source bundle).
- Checksum still mismatches after `cache-clear` and `resync`.
- A critical endpoint group has been on stale signatures for over 24 hours.
