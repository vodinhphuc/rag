
# Runbook: Collector quá tải, agent bị throttle (SQ-2011)

## Triệu chứng

Agent hiển thị offline trên Console. Một số endpoint ngừng gửi telemetry, số còn
lại vẫn bình thường. Người dùng không báo bất thường.

Dấu hiệu riêng của `SQ-2011`:

- Alert `SQ-2011` trên một hoặc nhiều collector node.
- **Console → Infrastructure → Collectors** hiển thị queue depth vượt ngưỡng.
- Log agent ghi `throttled by collector`, không phải lỗi kết nối.

## Chẩn đoán

**1. Xác định collector bị ảnh hưởng**

```
sentriqctl collector status
```

Xem cột `queue_depth` của từng node. Ngưỡng là **10.000 event**. Vượt ngưỡng này
collector bắt đầu throttle agent, Console hiển thị thành Offline.

**2. Kiểm tra event store**

```
sentriqctl store health
```

Nếu store báo shard chưa được gán, collector bị dồn ứ là do store không nhận ghi.
Trường hợp đó chuyển sang runbook **D09**.

## Xử lý

**1. Giải phóng backlog**

```
sentriqctl collector flush --node sq-collector-02
```

Lệnh này xả toàn bộ queue. Thời gian hoàn tất phụ thuộc kích thước queue, thường
khoảng 5 phút. Agent trở lại Online mà không cần restart.

**2. Không restart agent**

Agent không lỗi. Restart chỉ làm tăng tải handshake lên collector đang quá tải.

**3. Tìm nguyên nhân**

```
sentriqctl collector top-talkers --node sq-collector-02
```

Thường do một endpoint sinh quá nhiều file event vì cấu hình exclusion sai. Nếu
đúng, chuyển sang runbook **D10 — Xung đột exclusion (SQ-5013)**.

## Khi nào escalate

- Sau 30 phút queue depth vẫn vượt ngưỡng.
- Từ hai collector node trở lên cùng vượt ngưỡng.
- Lệnh flush trả về lỗi.
