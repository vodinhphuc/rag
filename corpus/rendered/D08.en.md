
# Runbook: Collector back-pressure, agents throttled (SQ-2011)

Applies to SENTRIQ 4.2.

## Symptoms

Agents show as offline on the Console. Telemetry stops arriving for some
endpoints while others continue normally. Users report nothing unusual.

> This opening symptom is **identical to `SQ-6008`** (runbook D09). The two are
> distinguished by which component reports the fault, not by what NOC observes.
> Read the diagnosis section before acting.

Additional signals specific to `SQ-2011`:

- Alert `SQ-2011` on one or more collector nodes.
- **Console → Infrastructure → Collectors** shows queue depth above threshold.
- Agent logs show `throttled by collector`, not a connection failure.

## Diagnosis

**1. Identify the affected collector**

```
sentriqctl collector status
```

Read the `queue_depth` column for each of the three nodes. The threshold in 4.2
is **50,000 events**. Above it the collector begins throttling agents, which the
Console renders as Offline.

**2. Determine whether the store is accepting writes**

This is the step that separates `SQ-2011` from `SQ-6008`.

```
sentriqctl store health
```

- **Store healthy, queue depth high** → genuine collector back-pressure. Continue
  with this runbook.
- **Store reports unassigned shards** → the collector is backed up *because the
  store stopped accepting writes*. This is `SQ-6008`. **Switch to runbook D09 and
  treat it as P1.** Draining the collector here will not help and loses telemetry.

## Resolution

Only when the store is healthy.

**1. Drain the backlog**

```
sentriqctl collector drain --node sq-collector-02 --rate 5000
```

Drains at 5,000 events per second. Expect roughly ten minutes for a queue at
threshold. Throttling releases progressively as the queue falls; agents return to
Online without needing a restart.

**2. Do not restart agents**

Agents are not faulty. Restarting them adds re-handshake load to a collector that
is already saturated.

**3. Identify what caused the surge**

```
sentriqctl collector top-talkers --node sq-collector-02 --last 1h
```

A single noisy endpoint — usually one with a misconfigured exclusion producing
excessive file events — accounts for most surges. If so, continue with runbook
**D10 — Exclusion conflict (SQ-5013)**.

## When to escalate

- Queue depth still above threshold 30 minutes after drain starts.
- Two or more collector nodes above threshold at once.
- Drain command returns an error.
