# Agent installation guide (Linux)

Applies to SENTRIQ 4.2 on RHEL 8+, Ubuntu 20.04+ and Debian 11+. The agent runs as
a systemd service and needs a kernel module for real-time telemetry.

## Prerequisites

- Root or sudo on the target endpoint.
- Kernel headers matching the running kernel (the module builds against them).
- Network reachability to sq-policy on 7443 and sq-collector on 8443.
- The enrolment token from Console → Fleet → Enrolment.

## Step 1 — Install the package

```
sudo dpkg -i sentriq-agent-4.2.deb        # Debian/Ubuntu
sudo rpm -i sentriq-agent-4.2.rpm         # RHEL
```

The post-install script builds the kernel module. If kernel headers are missing
the build fails and the agent falls back to a reduced-telemetry mode — it enrols
and reports Online, but collects less. Confirm the module loaded.

## Step 2 — Enrol

```
sudo sentriqctl enrol --token <token>
```

## Step 3 — Confirm the module and service

```
systemctl status sq-agent
lsmod | grep sentriq
```

If `lsmod` shows nothing, the module did not load — install kernel headers and
re-run the post-install. Online-but-no-module is the most common silent Linux
misconfiguration: the endpoint looks protected but real-time detection is
degraded.

## Step 4 — Verify enrolment and telemetry

```
sentriqctl cert show
```

Confirm the endpoint is Online in the Console within five minutes.

## Secure Boot

On endpoints with Secure Boot enabled the kernel module must be signed with an
enrolled key, or it will not load. Enrol the Sentriq signing key via `mokutil`
before installing, or the agent runs in reduced-telemetry mode permanently.

## Uninstall

```
sudo sentriqctl unenrol --token <token>
sudo dpkg -r sentriq-agent               # or rpm -e
```

Tamper protection blocks removal without the token. Prefer Retire from the
Console. See D06 for offline troubleshooting.
