# Runbook: Detection rule compilation failure (SQ-3009)

Applies to SENTRIQ 4.2. **English only** — no Vietnamese or Japanese version
exists for this runbook.

## Symptoms

- Alert `SQ-3009` from `sq-detect`.
- **Console → Detections → Rules** shows one or more rules in state `FAILED`.
- Detections that depended on the failed rule stop firing. Nothing else breaks,
  which is what makes this dangerous: the system looks healthy.

## Why this matters more than it appears

A failed rule is silent. No endpoint goes offline, no queue backs up, no user
complains. The only visible effect is that a class of detection stops happening,
and that is invisible until something goes undetected.

Treat a failed rule as a **detection gap**, not a cosmetic error.

## Diagnosis

**1. List failing rules**

```
sentriqctl detect rules --state FAILED
```

**2. Read the compiler output**

```
sentriqctl detect rule-explain --id <rule-id>
```

Common causes, in rough order of frequency:

| Cause | What the compiler says | Fix |
|---|---|---|
| Field renamed by a schema change | `unknown field: process.parent.hash` | Update the rule to the new field name |
| Regex too expensive | `pattern rejected: backtracking limit` | Rewrite without nested quantifiers |
| Reference to a deleted lookup list | `unknown list: corp_admin_accounts` | Restore the list or remove the reference |
| Rule bundle partially applied | `dependency not compiled: <id>` | Recompile the whole bundle, not the single rule |

**3. Check whether a bundle deployment is the trigger**

```
sentriqctl detect bundle-history --last 7d
```

If the failure timestamp matches a bundle deployment, the deployment is the cause
and the whole bundle should be rolled back rather than the single rule patched.

## Resolution

**Single rule, known fix**

```
sentriqctl detect rule-apply --file <rule.yaml>
sentriqctl detect rules --state FAILED   # confirm it cleared
```

**Bundle-wide failure**

```
sentriqctl detect bundle-rollback --to <previous-version>
```

Roll back first, investigate afterwards. A rolled-back bundle restores detection
coverage immediately; debugging with coverage down does not.

## Correlation window note

Rules using a correlation window longer than 15 minutes may report `SQ-3021`
(correlation window overflow) rather than `SQ-3009`. These are different faults —
`SQ-3021` is a capacity problem, not a syntax problem.

## When to escalate

- More than five rules failing at once.
- Rollback does not clear the failure.
- The failing rule covers a detection the SOC team has flagged as critical.
