# SENTRIQ Console: access, roles and permissions

## 1. Roles

SENTRIQ ships five built-in roles. They are not customisable in 4.2; custom roles
arrive in 4.3.

| Role | Can view | Can change | Typical holder |
|---|---|---|---|
| `viewer` | Dashboards, alerts | Nothing | Management, auditors |
| `noc-operator` | Alerts, endpoint health, runbook links | Acknowledge alerts, retire endpoints | NOC tier 1 |
| `soc-analyst` | Everything `noc-operator` sees, plus raw telemetry and detection detail | Alert triage state, false-positive marking | SOC tier 2 |
| `engineer` | Everything | Policy, exclusions, detection rules | Product engineering |
| `admin` | Everything | Everything, including roles | Platform team |

**`noc-operator` cannot read raw telemetry.** This is deliberate and is the most
frequent source of confusion during handover: an operator following a runbook
step that says "check the process tree" will see an empty panel rather than an
error. The step requires `soc-analyst`.

## 2. Session behaviour

Console sessions are held in the session store, not in the browser.

| Setting | Default | Notes |
|---|---|---|
| Idle timeout | 30 minutes | Not configurable in 4.2 |
| Absolute session lifetime | 12 hours | Re-authentication required after |
| Concurrent sessions per user | 3 | Fourth login evicts the oldest |

### 2.1 SQ-4002 — session store unavailable

If the session store is unreachable the Console returns `SQ-4002` and **every user
is logged out simultaneously**. This looks like a total outage and is usually
mistaken for one.

Confirm before escalating:

```
sentriqctl console session-store-health
```

The alert clears on its own once the store returns. Detection and telemetry
collection are **unaffected** — only the user interface is down. Endpoints
continue to be protected throughout, and this is the single most useful fact to
state when the incident is reported.

## 3. Authentication

SAML and LDAP are supported. Local accounts exist only for the initial `admin`
and should be disabled after the identity provider is connected.

Group-to-role mapping is configured under **Console → Settings → Identity → Role
mapping**. Mappings are evaluated top to bottom and **the first match wins** —
a user in both the NOC and SOC groups receives whichever role is listed higher,
not the more permissive of the two.

## 4. Access review

Export the current role assignments:

```
sentriqctl console roles export --format csv
```

Review quarterly. The export includes last-login timestamps, which is the
practical way to find accounts belonging to people who have left.

## 5. Common access problems

| Symptom | Cause | Resolution |
|---|---|---|
| User sees empty panels, no error | Role lacks the permission for that data | Check role against §1 |
| All users logged out at once | `SQ-4002` — session store | §2.1; no action needed at the endpoint |
| User has the wrong role after a group change | First-match-wins mapping | Reorder mappings, §3 |
| Login loop after SAML change | Clock skew over 5 minutes | Verify NTP on the Console host |
