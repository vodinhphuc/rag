# False-positive handling procedure

Applies to SENTRIQ 4.2. For NOC tier 1 and SOC tier 2.

## When an alert is a false positive

A detection is a false positive when the flagged behaviour is legitimate and has
been verified. Do not mark an alert as a false positive because it looks familiar
or because a rule was just deployed. Familiar does not mean harmless.

> **Warning.** Marking false positives out of habit is one of the most dangerous
> mistakes. Genuinely malicious behaviour can resemble an old false positive. When
> unsure, escalate to SOC to investigate rather than closing the alert.

## Classify before acting

| Situation | Action |
|---|---|
| A legitimate internal binary is flagged | Add to the detection allowlist |
| Purchased commercial software is blocked | Allowlist by hash, with proof of purchase |
| A new rule produces too many alerts | Tune the rule, do not allowlist per machine |
| Unfamiliar behaviour, not clearly benign | **Do not** mark as a false positive. Escalate to SOC |

## Procedure

**1. Confirm the binary is legitimate**

```
sentriqctl detect explain --alert <alert-id>
```

Returns the hash, path, and the rule that fired.

**2. Mark the false positive**

```
sentriqctl detect mark-fp --alert <alert-id> --reason "<reason>"
```

A reason is mandatory and is retained for later review.

**3. Allowlist if it will recur**

Allowlist by hash, never by path — paths are easy to abuse.

```
sentriqctl detect allowlist-add --hash <sha256>
```

**4. If a broad rule is the cause**

When one rule produces many false positives, the problem is the rule, not the
machines. Hand it to the Detection team to tune. See D11.

## When a policy-side exclusion is also needed

If the false positive causes the agent to scan slowly or block a legitimate file
at runtime, a policy exclusion at sq-policy may be needed alongside marking the
false positive. See D10. These are two separate actions: marking the false
positive handles the detection side, an exclusion handles the scanning side.

## When to escalate

- Suspicious behaviour that is not clearly a false positive.
- A rule producing over 100 alerts per day.
- Any alert involving admin accounts or tamper protection.
