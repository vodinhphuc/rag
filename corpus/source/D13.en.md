# SOC alert triage playbook

Applies to SENTRIQ 4.2. For SOC tier 2. NOC tier 1 escalates detection alerts
here; this playbook decides what to do with them.

## Triage order

Work alerts in this order regardless of arrival time:

1. Alerts on tamper protection or the agent itself.
2. Alerts on admin or service accounts.
3. Alerts correlated across more than one endpoint.
4. Everything else, by severity.

An alert on tamper protection means something tried to disable the agent. Treat
it as active until proven otherwise; it outranks a higher-severity alert
elsewhere.

## Deciding the disposition

| Disposition | Condition | Action |
|---|---|---|
| True positive | Confirmed malicious or policy-violating | Contain, then follow incident response |
| False positive | Verified benign (see D14) | Mark as a false positive, tune if the rule is noisy |
| Benign true | Real but authorised (admin tool, pentest) | Suppress with an expiry, note the authorisation |
| Needs data | Cannot decide from the alert alone | Pull the process tree and raw telemetry |

## Pulling context

An alert is a summary. The decision usually needs the raw telemetry behind it:

```
sentriqctl detect timeline --alert <alert-id>
```

This requires the `soc-analyst` role — a `noc-operator` sees an empty panel here,
which is the most common handover confusion (see D16 on roles).

## Containment

If the disposition is true positive and the host must be isolated:

```
sentriqctl respond isolate --endpoint <id> --reason "<ticket>"
```

Isolation cuts the host off the network but keeps the agent's link to the
collector, so telemetry continues during investigation. Lift it with
`respond release`.

## Correlation across endpoints

An alert that fires on many endpoints at once is either a real campaign or a
noisy rule. Check the rule's recent false-positive rate before assuming a
campaign; a rule that suddenly fires everywhere after a deploy is usually the
deploy, not an attacker (see D11 on rule failures).

## When to escalate beyond SOC

- Confirmed compromise of an admin account.
- Tamper protection defeated, not just attempted.
- A detection gap: alerts that should have fired and did not.
