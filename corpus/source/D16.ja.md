# SENTRIQ Console: アクセス、ロール、権限

## 1. ロール

SENTRIQ には 5 つの組み込みロールがある。4.2 ではカスタマイズ不可。カスタム
ロールは 4.3 で提供予定。

| ロール | 参照可能 | 変更可能 | 主な利用者 |
|---|---|---|---|
| `viewer` | ダッシュボード、アラート | なし | 管理職、監査 |
| `noc-operator` | アラート、エンドポイント状態、runbook リンク | アラート確認、エンドポイントの retire | NOC tier 1 |
| `soc-analyst` | `noc-operator` の範囲に加え、生テレメトリと検知詳細 | トリアージ状態、誤検知マーク | SOC tier 2 |
| `engineer` | すべて | ポリシー、exclusion、検知ルール | 製品エンジニアリング |
| `admin` | すべて | ロールを含むすべて | Platform チーム |

**`noc-operator` は生テレメトリを参照できない。** これは意図的な設計であり、
引き継ぎ時の混乱の最大の原因である。runbook の「プロセスツリーを確認する」
という手順を実行しても、エラーではなく空のパネルが表示される。この手順には
`soc-analyst` が必要。

## 2. セッションの挙動

Console のセッションはブラウザではなく session store に保持される。

| 設定 | 既定値 | 備考 |
|---|---|---|
| アイドルタイムアウト | 30 分 | 4.2 では変更不可 |
| セッション最大有効時間 | 12 時間 | 経過後は再認証が必要 |
| ユーザーあたり同時セッション数 | 3 | 4 つ目のログインで最古を破棄 |

### 2.1 SQ-4002 — session store 利用不可

session store に到達できない場合、Console は `SQ-4002` を返し、**全ユーザーが
同時にログアウトされる**。全体障害に見えるため、実際に誤認されることが多い。

エスカレーション前に確認すること:

```
sentriqctl console session-store-health
```

store が復旧すればアラートは自動的に解消する。検知とテレメトリ収集には**影響
しない** — 停止しているのは UI のみである。その間もエンドポイントは保護されて
おり、これは障害報告時に伝えるべき最も有用な事実である。

## 3. 認証

SAML と LDAP に対応。ローカルアカウントは初期 `admin` のみで、ID プロバイダ接続
後は無効化すること。

グループとロールの対応は **Console → Settings → Identity → Role mapping** で設定
する。マッピングは上から順に評価され、**最初に一致したものが適用される** —
NOC と SOC 両方のグループに属するユーザーには、権限の広い方ではなく、上に記載
されている方のロールが割り当てられる。

## 4. アクセス棚卸し

現在のロール割り当てをエクスポートする:

```
sentriqctl console roles export --format csv
```

四半期ごとに確認すること。エクスポートには最終ログイン日時が含まれ、退職者の
アカウントを見つける実務的な手段となる。

## 5. よくあるアクセス上の問題

| 症状 | 原因 | 対応 |
|---|---|---|
| パネルが空でエラーも出ない | ロールに当該データの権限がない | §1 でロールを確認 |
| 全ユーザーが同時にログアウト | `SQ-4002` — session store | §2.1。エンドポイント側の対応は不要 |
| グループ変更後にロールが想定と異なる | 最初に一致したものが適用される | §3 に従い順序を変更 |
| SAML 変更後にログインループ | 5 分を超える時刻ずれ | Console ホストの NTP を確認 |
